# HR Analytics — End-to-End Data Project

An end-to-end people-analytics project on a synthetic dataset for a fictional
Indonesian tech company (**Nusantara Tech**, ~4,500 employees). It walks through
the full workflow a data analyst owns in the real world:

**Raw messy data → cleaning → SQL modelling → analysis & insight → dashboard.**

> Built to demonstrate practical skills across SQL, Python, and BI — from
> hands-on data cleaning to decision-ready insight.

---

## Why this project

Most portfolio projects use a clean, well-known dataset and jump straight to a
chart. Real analyst work starts with messy data and ends with a recommendation
someone acts on. This project is built to show that full arc on data I control,
so each stage — cleaning, joining, analysing — is visible.

## The questions it answers

1. **Attrition** — who is leaving, and what predicts it? (satisfaction, pay
   vs. band, tenure, level)
2. **Performance** — how does goal achievement relate to review scores across
   departments?
3. **Compensation** — are there pay gaps across levels, departments, or gender
   once we control for level?

## The data

Five related tables — `employees`, `departments`, `salaries`,
`performance_reviews`, `goals` — with a real manager hierarchy
(`employees.manager_id` self-references `employees.employee_id`). See
[`DATA_DICTIONARY.md`](DATA_DICTIONARY.md) for the full schema and the list of
deliberate data-quality issues in `raw/`.

All data is synthetic and generated by a seeded script, so the whole project is
reproducible: `python scripts/generate_hr_data.py`.

### Stage 1 — Data cleaning (done)

The raw exports in `data/raw/` carry realistic problems: duplicate rows, mixed
date formats, inconsistent gender/status labels, salaries stored as text
(`Rp30.100.000`), stray whitespace, and missing values. The cleaning stage:

- removes duplicates, standardises text/casing, maps categories to canonical values,
- parses mixed date formats into ISO dates, converts text-encoded numbers to numerics,
- handles missing values deliberately (fills only where a default is valid; never invents measured values),
- locks in types and runs **referential-integrity validation** (unique keys, valid foreign keys, real managers).

Two parallel implementations: a **step-by-step notebook** that explains every
decision, and a **modular production script** that runs the same pipeline
end-to-end. Output lands in `data/clean_rebuilt/`.
